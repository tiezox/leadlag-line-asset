# Bash でリポジトリの外へ cd しない

Claude のデスクトップアプリで動くときは、Bash でリポジトリの外のフォルダへ `cd` しない。リポジトリの外のファイルを扱うときは、`cd` せず、ファイルの場所をそのまま書いて渡す。WSL の中で `cd` する(`wsl.exe -e bash -lc 'cd ~/projects/<リポジトリ名> && …'`)のは、セッションの作業フォルダを変えないのでよい。

Bash が何も出さずに失敗し続けたら、まずセッションの作業フォルダを疑い、作業フォルダを移す道具(`change_directory`)で `~/projects/<リポジトリ名>` に戻す。移した後は `git status` で確かめる。`.git` が写っていないことがあるためで、無ければ、手元のファイルが GitHub と同じであることを確かめてから取り直す。

なぜ: デスクトップアプリでは、Bash で `cd` した先が、そのままセッションの作業フォルダになる。261114 に、Claude が長すぎる道具の結果を置くフォルダ(`C:\Users\tiezo\.claude\projects\…` の下)へ `cd` したところ、その場所が Windows の上限(260文字)を超えていたため、それ以降の Bash がすべて、何も出さずに失敗した。261115 にも、同じ形で作業フォルダが移った。
