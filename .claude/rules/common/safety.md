# 安全に関する決まり

## GitHub のリポジトリは常に非公開で作る

新しくリポジトリを作って push するときは、必ず非公開(private)にする。ユーザーが「公開にして」と明示したときだけ公開にしてよく、その場合は push 前に API キー・`.env`・秘密鍵がリポジトリに含まれていないかを確かめる。

```bash
gh repo create <name> --private --source=. --push
gh repo edit <owner>/<name> --visibility private
```

なぜ: 260419 に、既定で公開のまま push されたリポジトリにユーザーが気づいて驚いたことがあるためである。

## qwen 系のモデルは使わない

OpenRouter や Cerebras などでモデルを選ぶとき、qwen 系はすべて除外する。今後も追加しない。

なぜ: ユーザーがセキュリティ上の懸念から即時に禁止したためである。

## 破壊的な操作は許可を取ってから

アプリの再インストール、パッケージの削除やリセット、プロセスの強制終了、データを失うおそれのある操作は、ユーザーの許可なく実行しない。手順は次の3つの順で進める。

1. 壊さない代替手段(ログの確認、再起動の依頼)を先に試す。
2. 影響範囲を説明して許可を得る。
3. 特にデータを失うおそれがある操作は、その点を明示して確認する。

なぜ: 「起動しない」からといって即座に再インストールし、動いていた別のセッションを失ったことがあるためである。
