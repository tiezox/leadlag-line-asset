# Windows のフックのコマンドは、Git Bash で動く前提で書く

Windows の Claude Code(デスクトップアプリを含む)は、Git Bash が入っていると、フックのコマンドを Git Bash で動かす。Git Bash では、引用符で囲まない `\` が消えるので、`C:\Users\…` と書いた場所は `C:Users…` になり、コマンドが見つからずにフックが動かない。フックのコマンドの場所は `/` で書き、`"` で囲む(例: `"C:/Users/tiezo/AppData/Local/Programs/Python/Python313/python.exe" "C:/Users/tiezo/.claude/hooks/block_secrets.py"`)。

フックを足したり直したりしたら、そのセッションで、止まるはずの操作と通るはずの操作を実際に試して確かめる。フックが効かないときは、「設定が読み込まれていない」と決めつけず、まず登録したコマンドを Git Bash でそのまま動かして、動くかを確かめる。

なぜ: 261115 に、`~/.secrets.env` を開く操作を止めるフックを `\` の場所で登録したところ、フックが一度も動かなかった。Claude は「このセッションでは設定が取り込まれていない。新しいセッションで効くはず」と決めつけたが、実際は Git Bash が `\` を消して、コマンドが見つからなかったのが原因だった。直すと、同じセッションの中ですぐに効いた。
